# Coding Style

This reference describes how code should be written across projects that use this baseline.

Treat these guides as language-neutral defaults. When a project uses a stack with stronger conventions, follow the local project context first and use these rules as the fallback.

Start with this reference and open only the topic files relevant to the current task. Treat copied reference guides as diagnostic material and review prompts, not hard lint rules.

- [Clean Code](../clean-code/RULES.md): naming, functions, comments, documentation, duplication, and refactoring.
- [Code Quality](../code-quality/RULES.md): complexity and code-smell diagnostics.
- [Object-Oriented Design](../object-oriented-design/RULES.md): object design, SOLID principles, and design patterns.
