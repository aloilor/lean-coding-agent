# Quality Pipeline (PHP / Laravel)

A deterministic quality gate for this Laravel repo, provisioned by the coding-agent baseline. It implements the determinism-in-the-loop model (`../agent-context/determinism-in-the-loop-pipeline.md`): the reviewer runs the gate against the exact worktree under review, uses the findings as an instrument panel, and returns blocking findings through the normal review-fix loop.

The baseline drops in `phpstan.neon.dist`, the ratchet seed `phpstan-baseline.neon`, and the gate script `scripts/quality-gate`. Execution is **reviewer-only**: there are no PostToolUse or git hooks, and the code reviewer runs the gate once after inventorying each review pass. Humans and other tools are not gated. Two setup steps remain: install the tools and add the Composer scripts.

## 1. Install the tools (one time)

```sh
composer require --dev \
    larastan/larastan:^3.0 \
    tomasvotruba/cognitive-complexity \
    phpstan/extension-installer \
    laravel/pint

# Allow the PHPStan extension installer plugin (auto-registers Larastan +
# the cognitive-complexity rule):
composer config --no-plugins allow-plugins.phpstan/extension-installer true

# Seed the ratchet against current code (grandfathers existing debt):
composer quality:baseline
```

## 2. Add the composer scripts

Merge into `composer.json`:

```json
"scripts": {
    "quality": [
        "pint --dirty --test",
        "phpstan analyse"
    ],
    "quality:style": "pint --dirty --test",
    "quality:report": "phpstan analyse --error-format=json --no-progress > static-report.json",
    "quality:baseline": "phpstan analyse --generate-baseline"
}
```

- `quality` — human-friendly interactive run (Pint check + PHPStan table).
- `quality:style` — formatting check only (Pint on git-modified files); console output, since formatting is fixes, not analysis findings.
- `quality:report` — runs PHPStan (Larastan + cognitive-complexity included) and writes **all static-analysis findings** to `static-report.json`. This is the one artifact the gate persists and the reviewer reads.
- `quality:baseline` — regenerates the ratchet after triage.

The gate (`scripts/quality-gate`) runs `quality:style` then `quality:report`, so `static-report.json` is regenerated on **every gate run**. The reviewer always generates a fresh artifact for the current review pass.

Add `static-report.json` to `.gitignore` — it is regenerated by the gate on every run, never committed. Do **not** ignore `phpstan-baseline.neon`; it is committed shared state.

## Execution layers

| Tier | Trigger | Severity | Covers |
|------|---------|----------|--------|
| Review | Code reviewer runs `sh scripts/quality-gate` after diff inventory | blocking review evidence | Reviewed changes |
| Commit (hard gate) | — not provisioned (reviewer-only by choice) | would block, and cover humans | add a git `pre-commit` calling `scripts/quality-gate` when you want it |
| CI (whole-repo ratchet) | duplication (`jscpd`), architecture (`deptrac`), full `phpstan analyse` | blocking in CI | not provisioned here — add to CI |

Review enforcement is blocking by design: unresolved in-scope findings block reviewer approval. Nothing hard-blocks edits or commits; a git `pre-commit` and CI ratchet checks would be separate enforcement layers if added later.

Complexity is evaluated during review because it is directly actionable against the reviewed change. Duplication and architecture are relationships *between* files, so they belong at the whole-repo CI tier, ratcheted — not scoped to touched files.

## Standing complexity objective

The shared `code-reviewer` instruction owns the ratcheted complexity acceptance policy. In-scope target complexity findings block approval; unrelated pre-existing findings remain outside the change scope.

## How the agents use it

**Reviewer** — treat the gate output as an instrument panel, not the assignment:

- After inventorying the diff, run `sh scripts/quality-gate` before semantic review. Read the freshly generated `static-report.json` and use that gate status as the deterministic evidence for this review; do not rely on a pre-existing artifact. If the gate skips because setup is incomplete, or no fresh report is produced, record missing verification rather than treating the run as clean.
- `BLOCK` when the reviewer-owned complexity acceptance policy is not satisfied.
- Run `git diff -- phpstan-baseline.neon` — **new suppressions are the highest-signal review catch.** A finding baselined instead of fixed is a blocking issue unless explicitly justified.
- PHPStan analyses the whole `app/`. Return change-caused findings in touched files to the implementer, flag ripple findings in untouched files without expanding fix scope, and leave unrelated pre-existing findings to the baseline. In-scope target complexity findings remain blocking until resolved or a shared stop condition applies.
- Do not re-list mechanical findings as your own; spend the budget on semantic review (wrong abstraction, misnamed concept, leaky interface).

## Cross-tool note

The shared `code-reviewer` instruction is the sole workflow execution point in both Claude Code and Codex. When the initializer upgrades a project created by an earlier baseline version, it removes only PostToolUse commands that invoke `scripts/quality-gate` and preserves unrelated hook configuration.
