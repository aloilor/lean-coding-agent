# create-specification override

Save specifications under `docs/spec/`, not the skill's default `/spec/`.

Keep the skill's filename convention unchanged: `spec-[a-z0-9-]+.md`, where the name starts with the high-level purpose (schema, tool, data, infrastructure, process, architecture, or design). Everything else about the skill's behavior stays as-is.

Example: `docs/spec/spec-process-team-invitations.md`.
