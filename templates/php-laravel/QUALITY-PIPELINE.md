# Quality Pipeline (PHP / Laravel)

A deterministic quality gate for this Laravel repo, provisioned by the
coding-agent baseline. It implements the determinism-in-the-loop model
(`agent-context/determinism-in-the-loop-pipeline.md`): the implementer fixes
mechanical slop before review; the reviewer audits how it was handled and owns
the semantic layer.

The baseline dropped in `phpstan.neon.dist`, the ratchet seed
`phpstan-baseline.neon`, the gate script `scripts/quality-gate`, and PostToolUse
hooks in `.claude/settings.json` and `.codex/hooks.json`. Enforcement is
**agent-only**: the two agents run the gate per edit. There is deliberately **no
git pre-commit hook**, so nothing hard-blocks a commit and humans/other tools are
not gated — add a commit or CI gate later if you want that (see below). Two steps
remain: install the tools and add the composer scripts.

## 1. Install the tools (one time)

```sh
composer require --dev \
    larastan/larastan:^3.0 \
    tomasvotruba/cognitive-complexity \
    phpstan/extension-installer \
    laravel/pint

# Allow the PHPStan extension installer plugin (auto-registers Larastan +
# the cognitive-complexity rule):
composer config --no-plugins allow-plugins.phpstan/extension-installer true

# Seed the ratchet against current code (grandfathers existing debt):
composer quality:baseline
```

## 2. Add the composer scripts

Merge into `composer.json`:

```json
"scripts": {
    "quality": [
        "pint --dirty --test",
        "phpstan analyse"
    ],
    "quality:style": "pint --dirty --test",
    "quality:report": "phpstan analyse --error-format=json --no-progress > static-report.json",
    "quality:baseline": "phpstan analyse --generate-baseline"
}
```

- `quality` — human-friendly interactive run (Pint check + PHPStan table).
- `quality:style` — formatting check only (Pint on git-modified files); console
  output, since formatting is fixes, not analysis findings.
- `quality:report` — runs PHPStan (Larastan + cognitive-complexity included) and
  writes **all static-analysis findings** to `static-report.json`. This is the
  one artifact the gate persists and the reviewer reads.
- `quality:baseline` — regenerates the ratchet after triage.

The gate (`scripts/quality-gate`) runs `quality:style` then `quality:report`,
so `static-report.json` is regenerated on **every** edit and every commit — the
reviewer never has to hope someone produced it.

Add `static-report.json` to `.gitignore` — it is regenerated by the gate on
every run, never committed. Do **not** ignore `phpstan-baseline.neon`; it is
committed shared state.

## Tiers

Both edit-tier triggers call the **same** script, `scripts/quality-gate`, which
regenerates `static-report.json` (all static-analysis findings) and runs the
formatting check — so the check is defined once and the artifact is always fresh.

| Tier | Trigger | Severity | Covers |
|------|---------|----------|--------|
| Edit (per edit) | PostToolUse hook — `.claude/settings.json` **and** `.codex/hooks.json` | advisory (exit 2 → feedback to the model; the edit already landed) | Claude Code + Codex |
| Commit (hard gate) | — not provisioned (agent-only by choice) | would block, and cover humans | add a git `pre-commit` calling `scripts/quality-gate` when you want it |
| CI (whole-repo ratchet) | duplication (`jscpd`), architecture (`deptrac`), full `phpstan analyse` | blocking in CI | not provisioned here — add to CI |

Enforcement is advisory by design: the hooks fire *after* the edit, so exit 2
informs the model rather than undoing the change. Nothing hard-blocks yet — a
git `pre-commit` (for a hard, human-covering gate) and CI ratchet checks are the
next layers when you want them.

Complexity is checked at the edit tier because it is per-file. Duplication and
architecture are relationships *between* files, so they belong at the whole-repo
CI tier, ratcheted — not scoped to touched files.

## How the agents use it

**Implementer** — after implementing, run the gate and resolve it before
handoff. The gate writes `static-report.json` for you:

```sh
sh scripts/quality-gate              # regenerates static-report.json; fix findings, or...
composer quality:baseline              # ...deliberately grandfather (rare, justified)
```

**Fix scope.** PHPStan analyses the whole `app/`, so `static-report.json` holds
findings across the project. Fix only the findings **your change caused in the
files you touched**. New findings your change ripples into *untouched* files (a
caller you did not open) — do **not** fix them for now; **flag them in the report**
for the reviewer and leave them in the artifact. Pre-existing unrelated findings
are grandfathered by the baseline, not yours to fix.

Record in the implementation report: gate result, any new
`phpstan-baseline.neon` entries with justification, and any flagged (unfixed)
ripple findings in untouched files.

**Reviewer** — treat the gate output as an instrument panel, not the assignment:

- Read `static-report.json` for the static-analysis findings — the gate keeps it
  current, so it is always present. If in doubt, regenerate with
  `sh scripts/quality-gate`.
- Run `git diff -- phpstan-baseline.neon` — **new suppressions are the
  highest-signal review catch.** A finding baselined instead of fixed is a
  blocking issue unless explicitly justified.
- Do not re-list mechanical findings as your own; spend the budget on semantic
  review (wrong abstraction, misnamed concept, leaky interface).

## Cross-tool note

Enforcement is cross-agent: both agents run the same gate per edit via PostToolUse
hooks (`.claude/settings.json` and `.codex/hooks.json`, same shape), and the
workflow instructions ship in the shared `implementer` / `code-reviewer` agents
installed to both `.claude/agents/` and `.codex/agents/`. It is **not** cross-
*user*: with no git pre-commit hook, a human committing directly is not gated.
Add a `pre-commit` calling `scripts/quality-gate` if you want that coverage.

**If `.claude/settings.json` or `.codex/hooks.json` already exist in this repo,**
the initializer did **not** overwrite them. Merge this `PostToolUse` entry into
the existing `hooks` block of each (both use the same shape):

```json
{
  "matcher": "Edit|Write",
  "hooks": [
    { "type": "command", "command": "sh \"$(git rev-parse --show-toplevel)/scripts/quality-gate\"" }
  ]
}
```
